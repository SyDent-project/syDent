# استرجاع بيانات عيادة من ملف «💾 نسخة احتياطية»

الملف هو ما ينزّله المالك من زر «💾 نسخة احتياطية» بالصفحة الرئيسية
(`sydent-backup-YYYY-MM-DD.xlsx`، الصيغة `sydent-backup/2`).

## ما الذي يرجع وما الذي لا يرجع

- **يرجع:** كل صفّ كان بالملف وغير موجود الآن بقاعدة البيانات (مرضى، مواعيد، جلسات، دفعات، أسنان، وصفات، مخابر، مصاريف، مخزون، إعدادات…).
- **لا يُلمس:** أي صفّ ما زال موجوداً، حتى لو تعدّل بعد تاريخ النسخة. الاسترجاع إضافةٌ فقط (`ON CONFLICT DO NOTHING`).
- **لا يرجع من الملف:**
  - الصور والملفات (الأشعة والمستندات)، لأنها بالتخزين السحابي لا بالملف.
  - رموز القفل (PIN)، لأنها لا تُصدَّر أصلاً.
- **ما أُضيف بعد تاريخ النسخة:** يبقى كما هو.

## الخطوات

1. احفظ الملف خارج المستودع (لا يُرفع أبداً؛ `.gitignore` يمنع `sydent-backup-*`).

2. حوّله إلى ملفات SQL:

   ```
   node scripts/backup-restore.js /path/sydent-backup-2026-10-20.xlsx --out /path/restore-out
   ```

   الخيارات:
   - `--to-owner <uuid>`: يُستعمل إذا أُعيد إنشاء الحساب بمعرّف جديد، فيُستبدل معرّف الحساب القديم بالجديد بكل الصفوف.
   - `--only patients,appointments`: لاسترجاع جداول بعينها فقط.
   - `--chunk 300`: عدد الصفوف بكل ملف.

3. شغّل `00-compare.sql` على المشروع (`nxkalpjrqvpglphmiuui`). لكل جدول يظهر عدد صفوف النسخة، وكم منها **مفقود الآن**. هذا هو حجم ما سيرجع.

4. شغّل الملفات المرقّمة بالترتيب، وكل ملف يعيد `inserted`.
   - كل ملف معاملة واحدة: إن فشل لا يغيّر شيئاً.
   - الـ triggers الخاصة بالجدول تُطفأ أثناء الإدخال وتعود بنفس المعاملة، فلا سجلّ تدقيق ولا إعادة كتابة لـ `updated_at`.
   - المفاتيح الخارجية تبقى مفعّلة. إن فشل ملف على مفتاح خارجي، أعد تشغيله بعد الملفات التي يعتمد عليها؛ إعادة التشغيل آمنة لأنها لا تكرّر شيئاً.

5. أعد تشغيل `00-compare.sql`: يجب أن يصبح `missing_now = 0` لكل جدول.

## تحقّق

- `scripts/prove-backup-restore.js` يفحص الذهاب والإياب عبر ملف xlsx حقيقي ضمن `validate.sh`.
- جُرّب الاسترجاع على مشروع التطوير بمعاملة أُلغيت بالكامل. النتيجة:
  - الصفوف رجعت مطابقة حرفياً لـ `to_jsonb`.
  - إعادة التشغيل لم تُدخل شيئاً.
  - لم يبقَ أي trigger معطّلاً.
